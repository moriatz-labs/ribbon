# __APP_TITLE__ Agent Contract

This application was generated by VSCD. `vscd.json` is authoritative for its selected DNS, backend, deployment, mail, and design-system adapters. Use the global `vscd-build` skill for provider linking, release work, and URL handoff.

## Provider contract

- Do not replace a provider by changing imports or workflow commands in isolation. Change the manifest selection, regenerate or apply the matching adapter files, and run `vscd check`.
- The backend adapter owns session, records, and storage through `src/lib/backend.ts`. Product UI must depend on that contract rather than importing Supabase or Firebase directly.
- Supabase projects keep migrations, explicit Data API grants, RLS, private Storage policies, and SQL policy tests. Firebase projects keep owner-scoped `firestore.rules` and `storage.rules` plus `firebase.json`.
- `pnpm dns` reads the selected DNS and deployment adapters from `vscd.json`. Hostinger and Cloudflare updates reject conflicting record types; Cloudflare records stay DNS-only.
- The generated GitHub workflow must match `providers.deployment.provider`. Vercel and Netlify secrets stay server-side and production releases occur only through reviewed GitHub Actions.
- Hostinger Mail is a separate optional capability. When selected, keep magic-link generation, database rate limiting, and delivery server-side. Otherwise use backend-managed authentication email.

## Non-negotiable design-system contract

- Install the exact `strawn` and `strawn-icons` versions recorded in the lockfile and import only from their package roots.
- Use Strawn primitives and icons before creating app-local equivalents. Product-specific compositions remain in this application.
- Tailwind, shadcn/ui, Lucide, direct Radix imports, and old `@paul/*` packages are forbidden.
- Keep `projectType: "application"` and never add private design-system clone, deploy-key, commit-pin, Vite alias, or TypeScript path wiring.

Before release, run `pnpm check`, run `pnpm vscd check <this-project-path>` from VSCD, execute the selected backend's policy tests, provision DNS through the selected adapter, and release through a pull request.

Never expose service-role/admin credentials, Hostinger or Cloudflare tokens, Vercel or Netlify tokens, or private deploy keys in browser-prefixed variables.
